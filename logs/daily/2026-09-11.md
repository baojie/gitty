## Why it matters

**Why do this?**

A file opened beside the diff had no menu on its tab, so copying its path or
blaming it meant finding the row in the tree again.

**What problem does it solve?**

The menu is the row's, not a second one written beside it, which is why an
unlisted file — an unchanged one opened from a link or a search hit, in the
Changes view — is given the menu the Working Tree would give it rather than
index items with nothing behind them. A search tab names a pattern, not a
file, and offers none.

**What does it affect?**

`contextMenus.ts`, `DiffHeader` and `RepoTab`; the manual and the CHANGELOG.
